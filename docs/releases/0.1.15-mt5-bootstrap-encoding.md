# 0.1.15 — naprawa uruchamiania mostu MT5

## Przyczyna

W 0.1.14 dodano polskie komunikaty w `mt5-bridge/start.ps1`, zapisanym jako
UTF-8 bez BOM. Uruchamiany przez aplikację Windows PowerShell 5.1 odczytywał
plik jako ANSI. Litery po błędnym dekodowaniu stały się m.in. znakami cytowania,
co powodowało błąd parsera przed wykonaniem bloku try i zapisem statusu.
Rodzic odrzucał stderr, a interfejs stale wyświetlał „Most jeszcze się uruchamia”.

Parser Windows PowerShell przed naprawą zgłaszał błędy linii 141–156,
w tym brak końca ciągu i brak zamknięcia try. Katalog danych aplikacji
zawierał jedynie EBWebView, bez pliku statusu i endpointu.

## Naprawa

- Start.ps1 zapisany jako UTF-8 z BOM, zgodnie z Windows PowerShell 5.1.
- Kontrola kodowania każdego pakowanego skryptu PS1 przed kompilacją aplikacji.
  Brak BOM lub niepoprawny UTF-8 przerywa budowanie instalatora.
- Natywny proces zapisuje stdout/stderr startu w `bridge-bootstrap-OWNER.log`.
- Odczyt statusu sprawdza zakończenie procesu PowerShell. Błąd startu trafia
  do interfejsu wraz z końcówką logu, także gdy skrypt nie utworzył statusu.
- Poprawka nie omija sprawdzania health, protokołu ani tożsamości mostu.
  Egzekucja nadal jest ograniczona do ręcznych zleceń DEMO.

## Weryfikacja

- Kontrola kodowania, TypeScript/Vite: PASS.

- Odbiór uruchomienia nowego instalatora z lokalnym MT5: NOT RUN.
- Wysyłanie zleceń podczas prac: 0.
