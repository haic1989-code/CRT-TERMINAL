# CRT Terminal 0.1.7 — poprawki po audycie

## Wprowadzone zmiany

- Każde uruchomienie aplikacji otrzymuje własny most, port i tożsamość sesji.
- Sprawdzanie wersji protokołu i instancji na odpowiedziach HTTP.
- Oddzielna obsługa braku API MT5 i utraty połączenia z brokerem.
- Limit czasu inicjalizacji oraz kontrolowany ponowny kontakt z API.
- Zablokowanie mieszania kont i instalacji MT5 w jednej sesji.
- Błędy pozycji, zleceń i historii nie są zamieniane w puste dane.
- Wybór symbolu odrzuca niezgodne lub niejednoznaczne aliasy i sprawdza symbol_select.
- Timeouty klienta, ograniczenie oczekiwania na blokadę API, logi uruchomienia.
- Natywne OHLC MT5, aktualizacja wskaźników i uzupełnianie historii po błędzie.
- Walidacja odpowiedzi rynkowych i portfelowych przed przyjęciem do interfejsu.
- TP bez ceny ma zero lotów; suma zysku uwzględnia faktyczny rozdział lotów.
- Etykiety zysku i straty planera korzystają z order_calc_profit w MT5,
  w walucie konta; wynik brutto nie obejmuje przyszłej prowizji ani swapu.
  Nieudany lub nieaktualny odczyt kalkulatora usuwa te etykiety.
- Weekend uwzględniany przy pokazywaniu sesji; brak ticków nie jest automatycznie uznawany za zamknięty rynek.
- Aktualizacja Vitest do 4.1.11; instalacja pakietów zgłosiła zero podatności npm.
- Zmiany publicznych grafik uruchamiają workflow instalatora.

## Ograniczenia i odbiór

Most nadal służy do odczytu i obliczeń. Nie wysyła zleceń.
Wymagany jest Python 3.13 x64 oraz zainstalowany MT5. Pakiety mostu są dołączone offline.
Zmiana konta wymaga ponownego uruchomienia CRT Terminal.

Kompilacja frontend i desktop: wykonana. Automatyczne testy oraz scenariusze
na żywym MT5 nie zostały uruchomione w ramach tej poprawki. Stare testy UI z
audytu wymagają dostosowania do bieżącego interfejsu i kontraktu protokołu v2.
Nie zmieniono formuł SMA/EMA/BB/RSI ani nie wykonano szerokiej przebudowy UI.
VWAP i profil TPO nadal mają charakter przybliżeń opisanych w audycie.

Odbiór na żywym MT5 powinien objąć: start, utratę/powrót brokera, brak odczytu
portfela, zmianę konta, warianty nazw symboli, dwie aplikacje oraz aktualizację
przy pozostawionym starym mostku. Przy nieodpowiadającym natywnym IPC może być
konieczny restart aplikacji; timeout HTTP nie przerywa funkcji biblioteki MT5.
